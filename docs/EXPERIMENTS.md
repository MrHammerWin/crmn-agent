# Протокол экспериментов

## Этапы

1. Инженерные тесты: корректность формул, ограничения бюджета, отсутствие утечки в декодер, исключение неизвестных исходов, обучение prior только на train, reset/step трёх настоящих сред.
2. Короткие реальные прогоны локальной Qwen 1.5B: проверить вызовы LLM, формат JSON, выполнение действий и запись траекторий. Четыре действия на эпизод — сознательно короткий технический режим. Его нельзя сравнивать с опубликованными результатами при полном горизонте.
3. Валидационный пилот с полными горизонтами, одинаковыми задачами и оценкой стоимости. Отдельно выбрать параметры и заморозить их.
4. Финальное сравнение на заранее отложенных задачах и воспроизведение современных сильных агентов. Без этого нельзя заявлять выполнение пункта о двух SOTA бейзлайнах.

## Бенчмарки

**ALFWorld.** Используются официальные текстовые `.tw-pddl` игры. Для train, validation и test соответствуют `train`, `valid_seen`, `valid_unseen`. Адаптер использует публичные допустимые команды и отключает запросы скрытых фактов и экспертных планов. В пилоте выбираются фиксированные игры; финальная оценка должна покрывать все необходимые типы задач и объявленный набор.

**TextCraft.** Установлена упаковка `textcraft==0.0.3` с рецептами. Это сторонняя упаковка среды из ADaPT. Семантика команд сохранена, но её seed-выборка не объявляется исходным разбиением ADaPT. Один seed не равен независимой задаче: конечная цель может совпадать при разных seed. `task_id` — хеш цели. Перед финальным сравнением требуются непересекающиеся по целевым предметам манифесты и проверка соответствия авторскому протоколу.

Упаковка содержит ошибки использования пути ресурсов и изменения порядка рецептов между reset. Адаптер передаёт реальный путь и создаёт свежую среду. `PYTHONHASHSEED=0` фиксирует порядок хеш-коллекций. Состав правил и фактическая цель записываются в траекторию.

Дополнительно проверена нативная семантика команд: один `craft` выполняет рецепт один раз; увеличение первого числа не повторяет рецепт. Обобщённые ингредиенты типа `planks` нужно заменять конкретным предметом, например `oak planks`. Эти правила теперь явно сообщаются всем агентам. Полный план GPT 5.6 Luna, полученный до уточнения правил, не достиг цели из-за этих двух ошибок. Он сохранён как неудачный запуск. Отдельный исправленный вручную положительный контроль проверяет достижение цели в среде и не считается успехом модели или CRMN.

**BabyAI-Text.** Используется открытый fork MiniGrid, указанный BALROG, закреплённый на commit `cf73dd148e51276bd675a37e3bfb0bf2b42329b2`. Пять типов: `goto`, `pickup`, `open`, `putnext`, `pick_up_seq_go_to`. `num_dists=0`, шесть действий, родные текстовые частичные наблюдения. Публичный BALROG выбирает тип в конструкторе до reset; адаптер дополнительно инициализирует RNG конструктора, чтобы парные прогоны были воспроизводимы. Семантика задач и переходов не меняется. Стандартная MiniGrid не подставляется молча.

## Контроль сравнения

- Одинаковые модель, публичные наблюдения, начальные задания, правила допустимых действий, лимит шагов и история для всех вариантов.
- Отдельно сравниваются расходы токенов и число вызовов. Одинаковый лимит шагов не равен одинаковому вычислительному бюджету.
- Для сравнения при равной стоимости нужны отдельные серии с одинаковыми суммарными ограничениями токенов на эпизод; короткий текущий прогон этого не доказывает.
- Абляции: без восстановления, без предсказаний, только карта, только план. Обычная рефлексия — отдельный baseline, а не абляция CRMN.
- Выполненные короткие абляции — технические проверки включения компонентов с общим замороженным prior. Для полного причинного анализа нужны одинаковые горизонты и бюджеты; при необходимости prior следует переобучать отдельно. В текущих локальных сериях горизонты различаются, поэтому их успешность не используется как доказательство эффекта отключения компонента.
- Настройка и обучение только на train/validation. Итоговый test не используется для выбора выгодных параметров.
- Повторная попытка после изменения промпта — новый запуск, а не замена неудачного результата старого.

## Статистика

Основная метрика — доля успешно завершённых эпизодов. Дополнительно: действия, токены, время, невалидный JSON, ошибки команд и случаи исчерпания бюджета. Для доли успеха рассчитывается Wilson CI. Для разности вариантов используется парный bootstrap по эпизодам с одинаковыми benchmark/task/seed. Не использовать отдельные шаги как независимые наблюдения. При нескольких повторениях одной цели необходим анализ с группировкой по `task_id`.

Маленькая выборка и нулевая разность не доказывают эквивалентность. Если эпизоды завершились техническими ошибками, это видно в `error_episodes`; такую серию нельзя выдавать за полноценную оценку планирования. Среды, отказавшие при reset, прерывают запуск и не превращаются в «проигранные агентом задачи».

## Заморозка и проверка задач

```bash
PYTHONHASHSEED=0 .venv/bin/crmn freeze-tasks --config configs/local_smoke.json --output local/validation_tasks.json
```

Для финального test конфигурация должна указывать `frozen_manifest`. Необходимо заранее сравнить `task_id` всех трёх разбиений. Простого различия диапазонов seed недостаточно.
